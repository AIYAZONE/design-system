## 原发布失败与修复

失败有两个阶段。tokens 的 Trusted Publisher 已过期，重建后的发布模式也需要调整；用户在独立浏览器保存配置后，run 44260976758 的 OIDC 凭证交换返回 201，授权恢复。design-system 的 Trusted Publisher 没有过期。

随后 tokens 发布返回 E422：包中缺少 `repository.url`，无法与来源证明中的 `https://github.com/AIYAZONE/design-system` 匹配。补齐 tokens 的 Git 仓库地址和目录，并增加发布前校验及缺失、不匹配配置的回归测试。采用总包 0.4.1 的新标签重新发布。

run 44262095027 的 tokens 发布返回 202：npm 已受理并生成来源证明，稍后可从 registry 安装。总包发布则因 CI 使用 npm 12.2.3，把 `release-packages/aiyazone-design-system.tgz` 解析为 GitHub 地址而返回 EALLOWGIT。修正为 `./release-packages/aiyazone-design-system.tgz`，以原 `v0.4.1` 重试，发布包源码和标签保持不变。

本地 npm 12.2.3 dry-run 复现旧两段路径的 EALLOWGIT；同目录加 `./` 后通过。官方 [2026-07-28 发布时扫描说明](https://github.blog/changelog/2026-07-28-npm-publish-time-malware-scanning-and-dual-use-metadata/) 表明新包需先扫描再开放安装，通常约五分钟，繁忙或不同内容可能超过十五分钟；202 受理和 Actions 成功不能代替 registry 安装验收。
