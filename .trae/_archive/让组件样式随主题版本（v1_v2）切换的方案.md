## 可行性结论
- 可行，且推荐提供两种并存的消费方式：
  1) 外层标识切换：在 `html`/`body` 上添加标识，主题 CSS 通过属性选择器切换变量 → 组件随变量变化
  2) 版本化样式引入：分别引入 v1/v2 的主题样式文件，组件依赖的变量值随所引入版本变化

## 方案A：外层标识切换（属性驱动）
- 做法：在主题 tokens 中为 v1/v2 变量分别添加选择器包裹：
  - `:root:not([data-jds-theme-version="v2"]) { /* v1 变量 */ }`
  - `:root[data-jds-theme-version="v2"] { /* v2 变量 */ }`
- 构建：生成一个合并的 `dist/themes.css`（或合并到 `index.css`）包含两个版本的变量；默认不加标识即走 v1，设置 `document.documentElement.dataset.jdsThemeVersion = 'v2'` 切到 v2
- 组件：保持使用 CSS 变量，不在组件内 import 主题文件；如需个别差异，可使用 `:host-context([data-jds-theme-version="v2"])` 做少量覆盖（尽量少用，优先变量）
- 辅助：提供 `switchTheme('v1'|'v2')` helper 改写 dataset 标识

## 方案B：版本化样式引入（文件驱动）
- 做法：继续生成 `dist/index.css`（v1）与 `dist/index-v2.css`（v2）；使用者通过手动引入对应版本文件来让组件应用对应版本变量
- 优势：简洁、易于 CDN/NPM 分发；不需要运行时切换逻辑
- 用法：默认引入 `index.css`，切换到 v2 时改为 `index-v2.css`

### 属性驱动（运行时切换）具体用法
- 引入：`index.css` + `themes-switch.css`
- 切换：在运行时设置 `document.documentElement.dataset.jdsThemeVersion = 'v2'` 切到 v2；移除或设为其他值恢复 v1。
- 注意：`themes-switch.css` 仅包含 v2 的变量与字体，结构样式仍由 `index.css` 提供。

### 产物清单（themes 构建）
- `dist/index.css`：v1（默认）
- `dist/index-v2.css`：v2（文件驱动）
- `dist/themes-switch.css`：属性驱动覆盖（在 `data-jds-theme-version="v2"` 时启用）

## 组件注意样式文件（按主题版本）
- 推荐做法：将组件依赖的样式差异抽象为变量，由 v1/v2 tokens 定义这些变量；组件只使用变量 → 随版本自然切换
- 如确需规则级别差异（非变量可表达）：
  - 在主题目录（`src/styles/themes/v1|v2`）添加组件注意样式覆盖文件（例如 `button.overrides.less`），在主题入口引入；最终打包进各自版本 CSS

## 实施要点
1. 在 v1/v2 tokens 里为变量集添加 `data-jds-theme-version` 选择器包裹（方案A）
2. 构建新增合并主题产物（`themes.css`），保留现有 `index.css/index-v2.css`（方案B）
3. 若需要组件级覆盖，在 `themes/v1|v2` 加入对应组件 overrides 并在主题入口引入
4. 提供 `switchTheme` helper（可选）与文档示例（两种使用方式）

## 你如何选择
- 想要运行时一键切换 → 选方案A（属性驱动）
- 想要简单按版本分发/引入 → 选方案B（文件驱动）
- 两者可并存：默认用文件驱动，保留属性驱动用于运行时动态切换场景
