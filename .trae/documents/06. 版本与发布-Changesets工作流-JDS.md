# 版本与发布：Changesets 工作流（JDS）

## 1. 目标
- 以 Changesets 管理多包版本与发布，生成变更日志，保持语义化版本与可追溯性。

## 2. 基本概念
- changeset 文件：描述包的变更类型（patch/minor/major）与备注。
- version：根据所有 changeset 更新包版本与 `CHANGELOG`。
- publish：将更新后的包发布到 NPM/私服；支持多包一次性发布。

## 3. 配置示例
```json
{
  "$schema": "https://unpkg.com/@changesets/config@2.3.1/schema.json",
  "changelog": ["@changesets/changelog-github", { "repo": "jackery/design-system" }],
  "commit": false,
  "access": "public",
  "baseBranch": "main",
  "updateInternalDependencies": "patch",
  "ignore": ["apps/*", "tooling/*"]
}
```

## 4. 使用流程
1) 创建变更：
```bash
pnpm changeset
# 选择变更包：core/icons/i18n/utils
# 选择变更类型：patch/minor/major
# 填写变更说明：中文/英文均可，建议简明扼要
```
2) 合入 PR：将 changeset 文件随改动一同合入 `main`。
3) 版本更新：
```bash
pnpm changeset version
# 自动更新各包版本与生成 CHANGELOG
```
4) 发布：
```bash
pnpm changeset publish
# 读取 .npmrc/NPM_TOKEN，发布到 registry
```

## 5. CI 集成（GitHub Actions 示例）
```yaml
name: release
on:
  push:
    branches: [main]
jobs:
  version-and-publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v3
        with: { version: 9 }
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          registry-url: 'https://registry.npmjs.org'
          cache: 'pnpm'
      - run: pnpm install --frozen-lockfile
      - run: pnpm changeset version
      - run: pnpm changeset publish
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
```

## 6. 规范与准则
- 一次改动对应一个 changeset；跨包变更在一条 changeset 中勾选多个包。
- 变更类型：bugfix 用 `patch`；新增特性用 `minor`；破坏性变更用 `major`。
- 变更说明：包含影响范围、升级指引与潜在风险。

## 7. 常见问题
- 忘记创建 changeset：在后续 PR 补充；发布前必须包含。
- 私服发布：将 `registry-url` 指向 Nexus，并在 CI 中注入私服 token。
- 回滚：删除错误 changeset，或以新 changeset 进行修正发布。

## 8. 成功指标
- 每次发布均有完整变更日志；版本一致性无遗漏。
- 发布失败率 < 2%；变更追踪可审计。

## 9. 消费指引（NPM/CDN）

### 9.1 NPM 安装
```bash
pnpm add @jackery/design-system
```

#### 文件驱动（推荐）
```ts
// v1 默认样式
import '@jackery/design-system/dist/index.css'
// 可选：v2 版本样式
// import '@jackery/design-system/dist/index-v2.css'

// 组件入口
import { JdsButton, JdsDialog } from '@jackery/design-system'
```

#### 属性驱动（运行时切换）
```ts
// 引入 v1 基础样式 + 运行时覆盖样式
import '@jackery/design-system/dist/index.css'
import '@jackery/design-system/dist/themes-switch.css'

// 切到 v2（仅变量与字体覆盖）
document.documentElement.dataset.jdsThemeVersion = 'v2'
// 回到 v1
delete document.documentElement.dataset.jdsThemeVersion
```

### 9.2 CDN 引入
```html
<!-- 文件驱动：v1 默认 -->
<link rel="stylesheet" href="https://cdn.example.com/@jackery/design-system/index.css">
<!-- 文件驱动：v2 -->
<!-- <link rel="stylesheet" href="https://cdn.example.com/@jackery/design-system/index-v2.css"> -->

<!-- 属性驱动（与 v1 同时引入，运行时切换） -->
<link rel="stylesheet" href="https://cdn.example.com/@jackery/design-system/themes-switch.css">
<script>
  // 切到 v2
  document.documentElement.dataset.jdsThemeVersion = 'v2'
</script>
```

### 9.3 构建产物对照
- `index.css`：v1 默认主题样式（结构 + 变量）
- `index-v2.css`：v2 主题样式（结构 + 变量）
- `themes-switch.css`：属性驱动覆盖（v2 变量与字体，仅在设置 `data-jds-theme-version="v2"` 时生效）

### 9.4 注意事项
- 组件样式依赖 CSS 变量，建议不要在组件内直接 import 主题文件；主题切换由全局样式负责。
- `@font-face` 为全局规则，通常仅在实际使用对应字体族时请求资源；如需严格只在 v2 定义字体，可将 v2 字体独立成文件并按需加载。
