# 门户全新深色科技风 UI 实施计划

## 摘要

以“用 AI 更快做页面”为首页核心，重做整个设计系统门户的视觉、导航和内容顺序。采用深蓝黑背景、清晰白字、少量冰蓝强调、真实页面演示，减少说明段落，让访客快速看懂用途并找到下一步。

本计划已确认的用户选择：

- 视觉：深色科技感。
- 首页重点：用 AI 更快做页面。
- 范围：整个门户，包含组件文档和示例站。
- 组件展示：深色外框，保留真实组件主题与 V1/V2/V3 切换。

技术方案沿用 TypeScript、Vite、Lit Web Components、现有 CSS/Less 和 Storybook。无需新增框架、动效库或 AI 服务。

## 当前状态分析

已读取本地 `http://localhost:5173/` 与现网 `https://design.aiyazone.com/` 的页面结构，并检查源码。浏览器截图工具暂不可用，视觉判断以页面结构与 CSS 为依据，实施后必须补充真实截图验收。

1. 本地首页在 `apps/portal/src/main.ts`，首屏标题是“人和 AI，共用一套标准”。内容按真实组件、交付链路、AI 检查、安装排列，仍围绕仓库工程说明展开，AI 使用入口不突出。
2. 现网首页有六块资源入口和大篇幅治理全景图，多个入口同等醒目，混有规划、内部术语和过时数量。
3. `design.md` 与根目录 `tokens.css` 定义了纸白、石墨、橙色的编辑式风格，已被本次明确的新方向取代，需要同步更新。
4. 页面来源不同：首页和架构页由 Vite 构建；AI 指南、AI 样例和图标页是静态 HTML；示例站单独构建；组件文档由 Storybook 构建。只改首页 CSS 无法完成全站统一。
5. 导航实现存在重复：公共 `site-header.js`、示例首页内联导航、Storybook 的 `manager.ts` 与 `manager-head.html`。公共导航尚未正确区分 AI 指南激活状态。
6. 示例站首页有“7 个核心组件”“100% 响应式”等硬编码数字，应移除。图标页自身有搜索、分类、大小切换和复制，可沿用。
7. AI 样例使用固定版本 CDN 包，提供资料、时区、通知、删除确认交互，没有 AI 服务或真实账户后端。现有 `check-ai-demo.mjs` 对这个 HTML 的 API、图标、样式与标签关联做静态校验。
8. 架构页现有主入口已经区分当前实现与未来工作；历史全景数据仍在 `architecture-data.ts` 和 `panorama.ts`。新设计应保留资料，避免把旧自评数据重新变成首页卖点。
9. 当前工作区干净。项目没有 Atlas 的 Backlog/SOP，指定项目记忆目录也不存在；本次按当前仓库事实规划，不新建其他项目的待办体系。

## 设计与内容决定

### 1. 视觉规范

| 项目 | 新规范 |
| --- | --- |
| 页面背景 | `#080D17` 深蓝黑 |
| 内容表面 | `#101827`，选中或抬高表面 `#172338` |
| 主要文字 | `#F3F6FC` |
| 次要文字 | `#AAB8CD`，承担解释且保持可读 |
| 分隔线 | `#2A3A52`，低对比背景装饰不可承载信息 |
| 主要操作 | `#80C7FF` 背景配 `#07111E` 文字 |
| 品牌 | 保留原 Z 标志与橙色标记，橙色不再铺满按钮和标题 |
| 圆角 | 控件 8px，主要演示容器 16px |
| 字体 | 中文使用苹方、微软雅黑回退；英文沿用品牌文字，代码使用 SFMono/Menlo |
| 布局 | 内容最大宽度 1200px，桌面左右留白 40px，手机 20px |
| 标题 | 首屏桌面 56px、手机 36px；正文 16px、行高 1.65 |
| 动效 | 操作反馈 160–220ms；首屏一次不超过 400ms 的淡入，减少动效设置下关闭 |

科技氛围来自真实界面、清楚的布局、蓝色焦点和演示区域背后极淡的静态网格。网格仅用于首屏，不铺满所有阅读页；不用漂浮粒子、打字机宣传、渐变字、密集发光边框。正文内容以开放布局和分隔线组织，卡片只用于演示、图标、示例和代码。

门户颜色使用独立的 `--portal-*` 变量。保留现有组件 `--zone-*` 主题，不把门户蓝色覆盖到全部库组件。

### 2. 全站导航

桌面顺序固定为：

`品牌｜首页｜AI 使用｜页面示例｜组件文档｜图标｜系统说明`

对应路径：

| 名称 | 路径 |
| --- | --- |
| 首页 | `/index.html`，同时识别 `/` |
| AI 使用 | `/ai-usage.html` |
| 页面示例 | `/examples/`，AI 示例作为该页突出入口 |
| 组件文档 | `/storybook/` |
| 图标 | `/icons/` |
| 系统说明 | `/architecture.html` |

`/ai-demo.html` 激活“页面示例”。移动端品牌与“菜单”按钮同一行，点击展开全部导航；支持 Escape 关闭、`aria-expanded`、关闭后焦点返回菜单按钮。主题版本切换放进示例页面工具栏，名称写“组件主题”，避免与门户深色风格混淆。

全站增加“跳到正文”入口，导航当前项同时显示下划线和 `aria-current`。页脚仅保留品牌、版权和必要链接，不再重复宣传。

### 3. 首页结构与定稿文案

首屏左侧约占 45%，右侧约占 55%；手机先文案后演示。桌面 1440×900 首屏内能看到标题、说明、两个入口和演示主要控件。

首屏内容：

- 小标题：`AIYAZONE 设计系统`，版本作为弱化辅助信息，从现有构建变量读取。
- 主标题：`用 AI，更快做出` / `统一风格的页面。`
- 说明：`把组件和样式说明交给 AI，帮你完成页面初稿。你可以先看示例，再按步骤开始。`
- 主按钮：`查看 AI 使用方法` → `/ai-usage.html`。
- 次按钮：`打开页面示例` → `/ai-demo.html`。
- 演示标题：`页面示例：账户设置`。
- 演示旁短说明：`参考组件说明完成的页面，可直接操作。`

右侧以真实账户设置小界面替代三个孤立组件：昵称输入、邮件通知复选框、保存按钮与状态提示。使用现有 `zone-button`、`zone-checkbox` 和有标签的原生输入框；演示表面保留组件真实主题。保存只更新本页演示状态，提示“演示设置已保存”，并显示“本页演示，不会修改真实账户”。不模拟实时 AI 生成过程。

首屏以下仅三组：

1. **“三步开始用 AI”**：`复制使用指令` → `告诉 AI 你要做什么页面` → `打开结果，检查内容和交互`。每步一个短句；显示可复制指令，不放源文件链路。
2. **“页面需要的基础，都在这里”**：`组件`（按钮、弹窗、下拉等）／`样式`（统一颜色、字号和间距）／`图标`。每项一句说明和直接入口；样式沿用已有主题文档 URL，不新造文档路径。
3. **“直接在项目里使用”**：展示 `pnpm add @aiyazone/design-system` 和复制按钮；CDN 放在可展开的“静态 HTML 接入”说明中，版本使用构建变量。

首页不展示治理架构、自评分数、CI 长清单或性能收益数字。“生成后仍需检查内容和交互”用一句普通说明表达。

### 4. AI 使用页

标题：`让 AI 使用这套组件做页面`。

顶部先显示“复制下面的指令，补充页面需求，交给你正在用的 AI 工具”。第一块是可复制指令，第二块是三步说明，再放“打开账户设置示例”。无需选模型或填写密钥。

指令定稿：

```text
请使用 AIYAZONE 设计系统制作一个【写下页面需求】。
先阅读 https://design.aiyazone.com/llms.txt。
需要组件细节时，继续阅读其中链接的完整说明。
使用说明中已有的组件、图标和样式变量。
没有现成组件的部分请说明，不要编造组件属性或事件。
输出可运行页面，并告诉我如何打开。
完成后检查按钮、表单、键盘操作和手机布局。
```

详细内容按“选组件”“统一样式”“检查页面”“技术参考”分组，用原生 `details` 展开。保留必要 API、变量名、检查命令与资料链接，首次出现技术词时先用中文解释。AI 文档提供参考、不能保证结果正确的边界合并为一段，不在每组反复重复。

### 5. 页面示例

`/examples/` 标题改为“页面与组件示例”，第一项突出“账户设置：看一个完整页面”。其余按“组件交互”“字体与多语言”“页面样式”组织为短列表，每项中文名称、一个短说明；去除硬编码统计和装饰 emoji。

`/ai-demo.html` 加公共深色导航、说明和页脚，主体仍是实际组件主题的账户设置界面。页面名改为“账户设置示例”，说明操作仅演示；保留时区选择、通知切换、删除确认与提示的真实交互，不接真实后端。

现有示例子页统一深色外框、页面标题、返回入口、代码样式和组件主题工具栏。把运行组件与字体样式测试明确包进 `.example-preview` 容器，保留其主题颜色与原有字体测试内容，避免深色正文覆盖演示。

### 6. 组件文档、图标、系统说明

- **组件文档**：Storybook 顶栏、侧栏、工具栏、文档正文改深色，继续保留检索、Controls、无障碍面板和既有 story ID。组件 Canvas 与文档内演示容器保留真实主题背景。通过 Storybook 官方主题和文档容器扩展设置，不依赖生成的 `.css-*` 类名。
- **图标**：顶部标题“找到图标，点击复制名称”，短说明先解释操作，用法代码放在折叠区。搜索、分类、大小工具统一深色；图标保持实际 SVG，颜色随展示区域文字颜色。加载失败显示“图标加载失败，请重试”，复制失败显示“复制失败，请手动复制”，不能显示假成功。
- **系统说明**：标题“这套设计系统包含什么”，按“组件、样式和图标”“文档如何生成”“目前会检查什么”呈现。源码目录与 API 术语放进可展开细节。未来规划放在页面末尾并明确标记；保留历史数据文件，不重新展示未经更新的成熟度数字。

## 接口、数据流与边界情况

1. 导航模块输出固定链接与由 pathname 推导的当前项；普通门户与 Storybook 只负责各自挂载，不能重复注入导航。
2. 共享 CSS 静态 URL 为 `/shared/site-theme.css`；门户 TS 和示例 TS 可从同一源文件导入，Storybook 通过静态目录提供相同路径。检查开发服务器和组装产物两种模式。
3. 首页版本继续来自 `__ZONE_VERSION__`；AI 样例固定 CDN 版本不自动改成未发布版本。
4. 首页演示在组件注册后初始化。输入有标签，保存反馈使用 `role="status"`；不存储真实资料，不请求 AI 或账户 API。
5. 复制 API 失败时尝试现有可选文本回退；仍失败则显示失败文字并提供手动复制。只有复制成功才显示“已复制”，状态按原按钮文字恢复。
6. 图标仍从已有 manifest 与 SVG 目录读取。搜索无结果保留空状态；网络失败支持重试。吸顶工具栏放在导航以下，不能遮住搜索与标题。
7. 主题只在示例路径使用 `theme=v1|v2|v3`，其他值回退 v1；跳转到其他门户路径去掉主题参数。门户深色不由该参数切换。
8. 演示和文档表格可能较宽，局部容器横向滚动，整页不能横向溢出。移动菜单展开不能覆盖无法访问的主要操作。
9. AI 样例内继续使用有效 `--zone-*` 与公共组件 API；门户共享样式属于页面外框。现有静态校验不能证明外链样式正确，所以补充浏览器验收，不删除或放宽既有检查规则。
10. 示例删除动作继续只演示确认和提示；所有提示用“演示”措辞，避免让访客误以为修改了实际账户。
