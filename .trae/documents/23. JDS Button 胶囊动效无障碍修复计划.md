# JDS Button 胶囊动效无障碍修复计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers` 或 `executing-plans` 按任务执行。步骤使用复选框追踪。

**目标：** 消除 `jds-button` 胶囊动效示例中的 nested-interactive 无障碍违规，同时保留当前“文字按钮 + 圆形箭头胶囊滑入”的视觉效果，并将该能力沉淀为组件级可复用能力。

**方案概述：** 当前违规不是 `jds-button` Shadow DOM 自身造成的，而是示例页把一个 `jds-button.only-icon` 嵌套进另一个 `jds-button`。修复方案保留现有 `interaction="shine"` 语义不变，新增一个独立的图标呈现模式，让胶囊尾缀图标由 `jds-button` 内部渲染为非交互装饰节点，从根源上避免可聚焦后代。

**技术栈：** Lit Web Components、Less、Vitest、axe-core、Storybook、Vite examples

---

## Summary
- 将胶囊尾缀从“外部嵌套子按钮”改为“组件内部装饰图标”，避免 `button` 嵌套 `button`。
- 保留 `interaction="shine"`，新增独立属性承载胶囊视觉，确保两种效果可以叠加。
- 同步更新 `packages/core` 组件源码、样式、Story、测试，以及 `apps/examples` 示例页。
- 清理 `src/styles/animate/animate-btn.less` 中对嵌套 `jds-button.only-icon` 的依赖，避免后续示例再次回退到违规写法。

## Current State Analysis

### 已确认事实
- 问题示例出现在 `apps/examples/pages/atoms/button.html`。
- 当前违规写法包括：
  - `interaction="shine"` 示例里的嵌套结构。
  - “实心胶囊动效按钮”章节里的 4 组嵌套结构。
- 违规根因是外层 `jds-button` 的 Shadow DOM 渲染出原生 `<button>`，而其 Light DOM 子节点里又放了另一个 `jds-button`，最终形成“可交互元素后代可聚焦”。
- `packages/core/src/components/button/index.ts` 当前只有 `interaction: "default" | "shine"`，没有承载胶囊尾缀的组件级 API。
- `packages/core/src/components/button/index.less` 已有成熟的按钮、图标、shine 动效体系，可以承接胶囊动画。
- `src/styles/animate/animate-btn.less` 当前通过 `jds-button.only-icon` 选择器驱动胶囊尾缀动画，这正是促成嵌套结构的样式前提。
- `packages/core/src/components/button/__tests__/button.a11y.test.ts` 已接入 `axe-core`，但还没有覆盖“胶囊动效 + 无嵌套交互后代”的回归用例。

### 范围判断
- 当前仓库里只有 `apps/examples/pages/atoms/button.html` 命中了“`jds-animate` + 嵌套 `jds-button.only-icon`”模式。
- 修复目标按你的选择定为“组件级方案”，并要求“保持现状视觉效果”。
- 本次不扩展到新的主题 token 设计，也不改动其他组件。

## Assumptions & Decisions
- 决策 1：保留 `interaction="shine"` 现有语义，不把胶囊效果塞进 `interaction` 枚举里，避免破坏“shine + 胶囊”叠加场景。
- 决策 2：新增独立属性 `iconMode`，取值为 `"inline" | "capsule"`，默认 `"inline"`。
- 决策 3：`iconMode` 反射为 kebab-case 属性 `icon-mode`，便于在 `index.less` 中以 `:host([icon-mode="capsule"])` 精确控制样式。
- 决策 4：`iconMode="capsule"` 只消费现有 `icon` 属性生成内部装饰图标，不支持从 `slot="icon"` 透传任意 Light DOM 节点进入胶囊模式。
- 决策 5：当不满足“有文本内容 + 有 `icon` + 非 text/secondary 退化场景”时，胶囊模式回退为现有 inline icon 布局，不做隐式 DOM 嵌套。
- 决策 6：移动端保持当前示例语义，即胶囊尾缀不强行展开；小屏优先保证无障碍和文本主操作清晰。

## Proposed Changes

### 1. 组件 API 与渲染层

**文件：** `packages/core/src/components/button/index.ts`

**要做什么**
- 为 `JdsButton` 新增类型与属性：
  - `export type ButtonIconMode = "inline" | "capsule";`
  - `@property({ reflect: true, attribute: "icon-mode" }) iconMode: ButtonIconMode = "inline";`
- 调整渲染分支，新增“胶囊尾缀”内部节点，而不是依赖外层传入子 `jds-button`。
- 保留现有 `icon` / `iconPosition` / `interaction="shine"` 能力，确保不破坏普通图标按钮。

**怎么做**
- 在 `render()` 中基于以下条件决定是否启用胶囊模式：
  - `this.iconMode === "capsule"`
  - `!!this.icon`
  - `this._hasDefaultSlot === true`
- 胶囊模式下渲染一个内部装饰节点，例如：
  - `<span class="capsule-icon" part="capsule-icon" aria-hidden="true">`
  - 内部再渲染 `<jds-icon ...>`
- 胶囊装饰节点必须是非交互元素，不绑定事件、不赋予 `tabindex`、不暴露为可聚焦后代。
- `iconMode="capsule"` 时不再使用 `<slot name="icon">` 作为胶囊载体，避免用户把 `jds-button` / `button` / `a` 之类可聚焦节点塞进来后再次复发问题。
- `href` 分支与 `<button>` 分支都复用同一套内部装饰节点，确保链接按钮也不存在交互嵌套。

**原因**
- 把视觉尾缀收敛到组件内部，才能从根源上保证 DOM 永远只有一个真实交互根。

### 2. 胶囊动画样式并入组件

**文件：** `packages/core/src/components/button/index.less`

**要做什么**
- 为 `icon-mode="capsule"` 增加专属样式和 hover/active 过渡。
- 复用当前 demo 的视觉尺寸映射，尽量保持“圆形箭头胶囊滑入”的表现一致。

**怎么做**
- 新增 `capsule-icon` 样式块，要求：
  - `pointer-events: none`
  - 默认缩放/位移隐藏，hover 时展开
  - 使用圆角、背景色、尺寸和 icon font-size 对齐现有 `.animate-variant(...)`
- 尺寸映射与现有 demo 保持一致：
  - `extra` / `large`：胶囊尺寸 `32px`，图标 `16px`
  - `medium`：胶囊尺寸 `24px`，图标 `12px`
  - `small`：胶囊尺寸 `12px`，图标 `12px`
- 只在主按钮语义下开启完整胶囊展开效果；`secondary` / `text` 若设置 `iconMode="capsule"`，回退为现有 inline 图标显示，不额外做圆形尾缀。
- 兼容与 `interaction="shine"` 叠加：shine 仍挂在 `.button::before/::after`，胶囊尾缀使用独立内部节点，不共享伪元素。
- 小屏断点下保留保守策略：胶囊节点可隐藏或退回静态 inline icon，但不能保留任何旧的嵌套结构依赖。

**原因**
- 动画放回组件内部后，examples/Storybook 不需要再通过嵌套组件配合全局样式“拼”视觉。

### 3. 示例页迁移到新 API

**文件：** `apps/examples/pages/atoms/button.html`

**要做什么**
- 把所有“外层 `jds-button` + 内层 `jds-button.only-icon`”示例替换为单个 `jds-button`。

**怎么做**
- 将以下区域迁移到新写法：
  - `interaction="shine"` 章节中的 `Hover interaction button`
  - “实心胶囊动效按钮”章节中的 extra / large / medium / small 四组按钮
- 统一改成类似下面的单组件写法：
  - `icon="arrow-right-long"`
  - `iconMode="capsule"`
  - 需要叠加扫光时继续保留 `interaction="shine"`
- 删除这些按钮内部的子 `jds-button.only-icon` 节点。
- 保留“纯图标动效按钮”卡片 demo，因为它本身不是嵌套交互结构；只要它依旧是单个按钮即可。

**原因**
- 示例页是当前违规的直接来源，必须同步迁移，否则新 API 落地后旧问题仍会在 examples 复现。

### 4. 清理 legacy animate 样式

**文件：** `src/styles/animate/animate-btn.less`

**要做什么**
- 删除或收缩“实心胶囊按钮”相关的 legacy 选择器，避免继续依赖 `jds-button.only-icon` 嵌套模式。
- 保留仍有用的“纯图标按钮卡片 hover 动效”样式。

**怎么做**
- 移除以下依赖嵌套子按钮的样式块：
  - `.jds-animate &[variant="primary"] ...`
  - 所有 `jds-button.only-icon` 作为外层按钮子节点参与布局/背景/尺寸的规则
- 若卡片 demo 仍需 `.jds-animate` 类，仅保留其对单个 `.only-icon` 按钮的外部 hover 控制。
- 更新注释，明确该样式文件只负责 examples 的“外部容器驱动动效”，不再承载按钮内部胶囊尾缀实现。

**原因**
- 若 legacy 样式不清理，后续维护者很容易再次照着旧示例写出嵌套按钮。

### 5. Storybook API 演示同步

**文件：** `packages/core/src/components/button/jds-button.stories.ts`

**要做什么**
- 暴露 `iconMode` 的控件与说明。
- 补一个胶囊尾缀示例，覆盖“普通胶囊”和“shine + 胶囊”两个主场景。

**怎么做**
- 在 `ButtonProps` 中补 `iconMode?: "inline" | "capsule"`.
- 在 `argTypes` 中新增 `iconMode`：
  - `options: ["inline", "capsule"]`
  - 文案说明：`capsule` 仅在有文本内容且提供 `icon` 时生效，用于非交互装饰尾缀。
- 新增或改造 story：
  - `CapsuleIcon`
  - `Interactions` 中增加 `interaction="shine" + iconMode="capsule" + icon="arrow-right-long"` 示例
- 移除 story 中若存在的旧嵌套示例写法，避免 Storybook 文档继续输出违规 DOM。

**原因**
- 组件公共 API 发生变化后，Storybook 必须成为新的权威示例来源。

### 6. 回归测试补齐

**文件：**
- `packages/core/src/components/button/__tests__/button.test.ts`
- `packages/core/src/components/button/__tests__/button.interaction.test.ts`
- `packages/core/src/components/button/__tests__/button.a11y.test.ts`

**要做什么**
- 为新增 `iconMode="capsule"` 补 DOM、交互与 a11y 回归。

**怎么做**
- `button.test.ts`
  - 断言 `iconMode` 默认值为 `"inline"`，设置后能正确反射到 `icon-mode="capsule"`。
  - 断言 `iconMode="capsule"` + `icon` + 文本内容时，Shadow DOM 内只渲染一个真实 `<button>` 或 `<a>`。
  - 断言胶囊尾缀节点为内部 `span` / `jds-icon`，而不是额外 `jds-button`。
  - 断言 `interaction="shine"` 与 `iconMode="capsule"` 可以同时存在。
- `button.interaction.test.ts`
  - 验证胶囊模式下点击、键盘触发仍正常。
  - 验证 `secondary` / `text` + `iconMode="capsule"` 不影响基础可点击行为。
- `button.a11y.test.ts`
  - 新增 `axe.run()` 用例覆盖 `iconMode="capsule"`。
  - 新增 DOM 结构断言，确保组件宿主或 Shadow DOM 中不存在额外的 `button` / `a[role="button"]` 后代。

**原因**
- 这是典型回归问题，必须用测试把“没有嵌套交互后代”锁死。
