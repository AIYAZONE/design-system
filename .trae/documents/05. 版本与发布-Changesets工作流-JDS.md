# 版本与发布：Changesets 工作流（JDS）

## 1. 目标

* 以 Changesets 管理多包版本与发布，生成变更日志，保持语义化版本与可追溯性。

## 2. 基本概念

* changeset 文件：描述包的变更类型（patch/minor/major）与备注。

* version：根据所有 changeset 更新包版本与 `CHANGELOG`。

* publish：将更新后的包发布到 NPM/私服；支持多包一次性发布。

## 3. 配置示例

```json
{
  "$schema": "https://unpkg.com/@changesets/config@2.3.1/schema.json",
  "changelog": ["@changesets/changelog-github", { "repo": "jackery/design-system" }],
  "commit": false,
  "access": "public",
  "baseBranch": "main",
  "updateInternalDependencies": "patch",
  "ignore": ["apps/*", "tooling/*"]
}
```

## 4. 使用流程

1. 创建变更：

```bash
pnpm changeset
# 选择变更包：core/icons/i18n/utils
# 选择变更类型：patch/minor/major
# 填写变更说明：中文/英文均可，建议简明扼要
```

1. 合入 PR：将 changeset 文件随改动一同合入 `main`。
2. 版本更新：

```bash
pnpm changeset version
# 自动更新各包版本与生成 CHANGELOG
```

1. 发布：

```bash
# 推荐：统一构建并发布（按 changeset 选择的包）
pnpm run release
# 等价于：pnpm run build && pnpm run changeset:publish
# 读取 .npmrc/NPM_TOKEN，发布到 registry
```

### 根包公开发布（NPM 公网）

```bash
# 确认 .npmrc 指向公网
# registry=https://registry.npmjs.com/

# 一键构建并发布根包
pnpm run publish:design-system

# 版本冲突（EPUBLISHCONFLICT）处理
npm version patch --no-git-tag-version
pnpm run publish:design-system
```

## 5. CI 集成（GitHub Actions 示例）

```yaml
name: release
on:
  push:
    branches: [main]
jobs:
  version-and-publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v3
        with: { version: 9 }
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          registry-url: 'https://registry.npmjs.org'
          cache: 'pnpm'
      - run: pnpm install --frozen-lockfile
      - run: pnpm changeset version
      - run: pnpm changeset publish
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
```

## 6. 规范与准则

* 一次改动对应一个 changeset；跨包变更在一条 changeset 中勾选多个包。

* 变更类型：bugfix 用 `patch`；新增特性用 `minor`；破坏性变更用 `major`。

* 变更说明：包含影响范围、升级指引与潜在风险。

## 7. 常见问题

* 忘记创建 changeset：在后续 PR 补充；发布前必须包含。

* 私服发布：将 `registry-url` 指向 Nexus，并在 CI 中注入私服 token。

* 回滚：删除错误 changeset，或以新 changeset 进行修正发布。

## 8. 成功指标

* 每次发布均有完整变更日志；版本一致性无遗漏。

* 发布失败率 < 2%；变更追踪可审计。

## 9. 消费指引（NPM/CDN）

### 9.1 NPM 安装

```bash
pnpm add @jackery/design-system
```

#### 文件驱动（推荐）

```ts
// v1 默认样式
import '@jackery/design-system/index.css'
// 可选：v2 版本样式
// import '@jackery/design-system/index-v2.css'

// 组件入口
import { JdsButton, JdsDialog } from '@jackery/design-system'
```

#### 属性驱动（运行时切换）

```ts
// 引入 v1 基础样式 + 运行时覆盖样式
import '@jackery/design-system/index.css'
import '@jackery/design-system/themes-switch.css'

// 切到 v2（仅变量与字体覆盖）
document.documentElement.dataset.jdsThemeVersion = 'v2'
// 回到 v1
delete document.documentElement.dataset.jdsThemeVersion
```

### 9.2 CDN 引入

```html
<!-- 文件驱动：v1 默认 -->
<link rel="stylesheet" href="https://f2e-cdn.jackery.com/@jackery/design-system/latest/dist/index.css">
<!-- 文件驱动：v2 -->
<!-- <link rel="stylesheet" href="https://f2e-cdn.jackery.com/@jackery/design-system/latest/dist/index-v2.css"> -->

<!-- 属性驱动（与 v1 同时引入，运行时切换） -->
<link rel="stylesheet" href="https://f2e-cdn.jackery.com/@jackery/design-system/latest/dist/themes-switch.css">
<script>
  // 切到 v2
  document.documentElement.dataset.jdsThemeVersion = 'v2'
</script>
```

### 9.3 构建产物对照

* `index.css`：v1 默认主题样式（结构 + 变量）

* `index-v2.css`：v2 主题样式（结构 + 变量）

* `themes-switch.css`：属性驱动覆盖（v2 变量与字体，仅在设置 `data-jds-theme-version="v2"` 时生效）

### 9.4 注意事项

* 组件样式依赖 CSS 变量，建议不要在组件内直接 import 主题文件；主题切换由全局样式负责。

* `@font-face` 为全局规则，通常仅在实际使用对应字体族时请求资源；如需严格只在 v2 定义字体，可将 v2 字体独立成文件并按需加载。

## 10. 私仓环境与发布命令清单

### 10.1 `.npmrc` 作用域与环境映射

```ini
registry=https://registry.npmjs.com/

# 生产环境
#@jackery:registry=https://nexus.hijackery.cn/repository/npm-private/

# UAT 验收环境
#@jackery:registry=https://nexus.hijackery.cn/repository/npm-private-stage/

# 开发环境
@jackery:registry=https://nexus.hijackery.cn/repository/npm-private-dev/

# 测试环境
@jackery:registry=https://nexus.hijackery.cn/repository/npm-private-test/

# 可选：开启强制认证与 token
#always-auth=true
#//nexus.hijackery.cn/repository/npm-private-test/:_authToken=<你的token>
```

说明：发布命令不带 `--registry`，按用户级 `.npmrc` 的 `@jackery:registry` 自动选择目标仓库。

### 10.2 Test/Dev 环境（支持同版本覆盖）

* 根包 `@jackery/design-system`

  * 登录（二选一）：

    * `npm adduser --registry https://nexus.hijackery.cn/repository/npm-private-test/`

    * 或在 `.npmrc` 写入：`//nexus.hijackery.cn/repository/npm-private-test/:_authToken=<token>`

  * 发布：`npm publish --access public`

* 子包逐个（按需）

  * `npm publish --workspace @jackery/core --access restricted`

  * `npm publish --workspace @jackery/utils --access restricted`

  * `npm publish --workspace @jackery/i18n --access restricted`

  * `npm publish --workspace @jackery/icons --access public`

* 批量（只发有版本变更的包）

  * `pnpm run build`

  * `pnpm run changeset:status`

  * `pnpm run version-packages`

  * `pnpm run release`

提示：如仓库允许重传，同版本可直接覆盖；如不允许，需先升版 `npm version patch --no-git-tag-version` 再发布。

### 10.3 生产环境（建议升版发布）

* 切换 `.npmrc`：`@jackery:registry=https://nexus.hijackery.cn/repository/npm-private/`

* 根包

  * 登录：`npm adduser --registry https://nexus.hijackery.cn/repository/npm-private/`

  * 升版：`npm version patch --no-git-tag-version`

  * 发布：`npm publish --access public`

* 子包逐个

  * `npm version patch --workspace @jackery/core --no-git-tag-version`

  * `npm publish --workspace @jackery/core --access restricted`

  * `npm version patch --workspace @jackery/utils --no-git-tag-version`

  * `npm publish --workspace @jackery/utils --access restricted`

  * `npm version patch --workspace @jackery/i18n --no-git-tag-version`

  * `npm publish --workspace @jackery/i18n --access restricted`

  * `npm version patch --workspace @jackery/icons --no-git-tag-version`

  * `npm publish --workspace @jackery/icons --access public`

* 批量（推荐生产流程）

  * `pnpm run build`

  * `pnpm run changeset:status`

  * `pnpm run version-packages`

  * `pnpm run release`

### 10.4 快速排查

* 查看当前作用域仓库：`npm config get @jackery:registry`

* 登录状态检查：`npm whoami`（默认 registry），或直接试 `npm publish` 看是否 `ENEEDAUTH`

* 常见错误：

  * `ENEEDAUTH`：未登录或 token 未配置在目标仓库作用域

  * `EPUBLISHCONFLICT`：版本已存在且仓库不允许覆盖；需升版
