# 组件开发与规范（JDS）

## 1. 目标

* 提供组件研发的统一流程、命名规范、API 设计、样式令牌、可访问性与测试要求，参考并对齐 Element Plus 的最佳实践。

## 2. 研发流程

* 需求评审：确认需求、API 草案、交互与无障碍要求。

* 设计对齐：确定设计令牌与主题变量；产出交互稿与边界态。

* 开发实现：基于 Web Components + Lit；遵循属性反射与事件冒泡。

* 文档与示例：Storybook 示例维度对齐；生成 API/事件/插槽表。

* 测试与验收：单元测试、交互测试、a11y 检查、性能与兼容性测试。

* 发布与回归：语义化版本、变更记录与迁移指引。

## 3. 命名规范

* 组件命名：`jds-*`，小写中横线，语义明确（`jds-button`、`jds-input`）。

* 属性命名：统一 `size`、`type|variant`、`disabled`、`loading`、`plain`、`round`、`circle`、`icon`、`text`。

* 事件命名：`click`、`input`、`change`、`focus`、`blur`；保持原生 DOM 冒泡与 `addEventListener` 兼容。

* 插槽命名：`prefix`、`suffix`、`default`；必要时 `header`、`footer` 语义化。

## 4. API 设计

* 一致性：不同组件的相同语义保持一致的属性/事件命名与行为。

* 可扩展：保留样式变量与受控/非受控两种使用模式；支持属性反射。

* 可访问：键盘导航、焦点管理、ARIA 标签；遵循 WCAG 2.1 AA。

## 5. 样式与设计令牌

* 变量命名：`--jds-color-*`、`--jds-radius-*`、`--jds-shadow-*`、`--jds-size-*`、`--jds-space-*`。

* 主题结构：基础 → 品牌 → 暗黑；允许项目级覆盖与扩展。

* 映射关系：提供与 Element Plus 变量的映射表与转换脚本。

## 6. 文档与示例

* 模板结构：概述 → 示例 → 属性 → 事件 → 插槽 → 样式变量 → a11y → FAQ。

* 示例维度：基础、状态（禁用/加载）、尺寸、图标、组合、国际化、RTL。

* 交互演示：使用 Storybook `play` 函数与 a11y 插件校验交互与可访问性。

## 7. 测试与质量

* 单元测试：Vitest，覆盖核心逻辑与属性/事件行为（覆盖率 ≥ 75%）。

* 交互测试：Storybook 交互用例；Chromatic 视觉回归（关键组件）。

* 性能测试：渲染基线与边界态；目标 60 FPS，渲染时间 < 16ms。

* 兼容性测试：现代浏览器 + 移动端；RTL 布局与国际化基本用例。

## 8. 构建与发布

* 产物：`esm`、`cjs`、`d.ts`、组件样式入口；支持按需加载与 Tree-Shaking。

* 版本：语义化版本；变更记录与迁移指引同步发布。

* 依赖：锁定主要依赖版本；安全扫描与升级策略。

## 9. 验收清单（Checklist）

* API 与行为符合规范，属性/事件/插槽命名一致。

* 文档模板与示例维度完整，示例可交互且可访问。

* 样式变量覆盖组件所有可配置维度；与主题映射表对齐。

* 测试通过，覆盖率达标；性能与兼容性测试完成。

* 版本与发布流程合规；变更记录与迁移指引完整。
