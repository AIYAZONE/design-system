# Trae Skills 使用指南（JDS）

> 文档日期：2026-01-16\
> 适用范围：Jackery Design System（JDS）仓库协作与 Trae 使用\
> 文档类型：使用指南

***

## 1. Skills 是什么

* Skills 是“仓库内的可复用执行规范”，用来把团队约定（目录结构、代码风格、测试门禁、发布流程）固化成可被 Trae 自动调用的指令集。

* Skills 不会替代代码与文档，它的作用是：当你提出常见需求时，让 Trae 更稳定地按 JDS 规范落地，减少反复解释与写法漂移。

## 2. Skills 怎么触发（你怎么用）

### 2.1 自然语言触发（推荐）

你只要把需求说清楚，Trae 会根据 skill 的描述自动匹配，例如：

* “新增 Input 组件，按 JDS 模板生成，带 tests + stories”

* “给 Dialog 增加 ESC 关闭，并补交互与 a11y 测试”

* “新增按钮 hover 背景 token，并分别给 v2/v3 不同值”

* “我要发布一个修复版，帮我生成 changeset 并写清楚验证步骤”

### 2.2 点名触发（可控）

如果你希望强制使用某个 skill，可以点名：

* “用 jds-component-scaffold 帮我新建 Input 组件”

* “用 jds-release-changeset 生成这次发布的 changeset 与检查清单”

## 3. 本仓库的 Skills 放在哪里

每个 skill 都是一个目录 + 一个 `SKILL.md`：

* 目录：`.trae/skills/<skill-name>/`

* 文件：`.trae/skills/<skill-name>/SKILL.md`

示例（本仓库已预置）：

* `.trae/skills/jds-component-scaffold/SKILL.md`

* `.trae/skills/jds-component-change/SKILL.md`

* `.trae/skills/jds-theme-token-workflow/SKILL.md`

* `.trae/skills/jds-release-changeset/SKILL.md`

## 4. SKILL.md 的写法规范（很重要）

`SKILL.md` 顶部必须有 frontmatter（yaml），关键是 `description`：

```md
---
name: "your-skill-name"
description: "做什么 + 什么时候用（触发语句/场景），尽量短，强触发词。"
---
```

### 4.1 description 的推荐写法

* 必须同时包含：

  * 做什么：这条 skill 负责的能力边界

  * 什么时候用：当用户说到哪些关键词/场景时调用

* 推荐包含“用户会怎么说”的关键词：新增组件 / 修复组件 / 发版 / token / 主题 等。

### 4.2 内容体的推荐结构

* 目标：这条 skill 保证交付到什么程度

* 关键位置：真实文件路径（越具体越好）

* 规则：不可违反的约束（例如 tokens、a11y、安全）

* 步骤：可操作的执行顺序（保持 6 步以内）

* 产出清单：最终必须交付的文件/改动

* 示例触发语句：给 3-6 条你常用的提问模板

## 5. 与 JDS 工程规范的映射（写 skill 时请引用这些）

### 5.1 组件目录与模板

* 组件位置：`packages/core/src/components/<name>/`

* 文件：`index.ts` + `index.less`

* 样式引入：`import styles from './index.less?inline'` + `unsafeCSS(styles)`

* 样式约束：只使用 `var(--jds-...)`；组件内禁止 `@import` 全局样式

### 5.2 测试栈与目录

* 测试框架：Vitest（jsdom）

* 交互：`@testing-library/user-event`

* 无障碍：`axe-core`

* 通用工具：`packages/core/test/utils.ts` 的 `mount` 与 `waitUpdate`

* 推荐结构：

  * `__tests__/<name>.test.ts`

  * `__tests__/<name>.interaction.test.ts`

  * `__tests__/<name>.a11y.test.ts`

### 5.3 Storybook

* Story 文件示例：`packages/core/src/components/button/jds-button.stories.ts`

* 推荐 title 风格：`03 基础组件/jds-<name>`

### 5.4 Tokens 与主题版本

* 基础 tokens 与 mixin：`src/styles/jds/tokens.base.less`

* 主题版本入口：`src/styles/themes/v1|v2|v3/`

* 组件 token：`src/styles/themes/v*/tokens/<component>.less`

### 5.5 发布与版本

* 工作流：Changesets + turbo + pnpm workspace

* 根脚本：`package.json` 的 `changeset:*`、`release`、`design:build`

## 6. 本仓库预置 Skills 说明（首批）

### 6.1 jds-component-scaffold

* 做什么：按 JDS 规范创建新组件骨架（Lit + less inline + tests + stories），并补导出。

* 什么时候用：新增组件、生成组件模板、按规范创建组件。

### 6.2 jds-component-change

* 做什么：修改现有组件并补齐 tests 与 stories，包含 a11y 与安全检查。

* 什么时候用：修复组件、增加属性、调整交互、回归测试。

### 6.3 jds-theme-token-workflow

* 做什么：新增/调整 tokens 与主题版本差异，并在组件样式中消费变量。

* 什么时候用：新增 token、调整主题色、主题版本差异、CSS 变量策略。

### 6.4 jds-release-changeset

* 做什么：根据变更类型建议版本号策略，生成 changeset 文案与发布检查清单。

* 什么时候用：发版、发布、生成 changeset、升级版本。

## 7. 维护与迭代建议

* 优先把“重复 3 次以上”的需求固化成 skill（例如：新增组件、补 a11y、发版清单）

* 当发现误触发/不触发：

  * 优先微调 `description` 的触发词与场景描述（这是最影响匹配效果的部分）

  * 再补充示例触发语句

* 当项目规范升级（目录/构建/发布策略变化）：

  * 先更新 `.trae/documents` 的规范文档

  * 再同步更新相关 skills 的关键路径与规则

## 8. 推荐提问模板（可直接复制）

* “新增 <Component> 组件，按 JDS 规范生成（含 tests + stories），并导出”

* “修复 <Component> 的 <行为>，补回归用例与 a11y”

* “把 <Component> 的 <样式/尺寸/颜色> token 化，禁止硬编码”

* “新增 <token>，并给 v2/v3 设置差异值，更新示例验证”

* “生成 changeset：这次改动是 \<patch/minor/major>，请写清验证步骤与影响范围”
