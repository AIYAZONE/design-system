# 主题与 Token 架构

## 总览
- 组件样式在 Shadow DOM 内，通过 `var(--zone-*)` 读取全局 CSS Variables。
- 主题（v1/v2）负责在全局 `:root` 与组件标签选择器（例如 `zone-button`）上定义这些变量。
- `src/styles/internal.less` 负责 normalize/reset/public/rte/animate 等基础样式；组件会在运行时把它注入到 ShadowRoot，保证跨站点一致性。

## 单主题切换方式
- 推荐方式：替换加载的 CSS 文件（例如从 v1 切到 v2，替换 `<link rel=\"stylesheet\">` 指向的文件）。
- 不支持也不建议“同一页面多主题并存”；主题以“全局单套生效”为原则。

## 关于 TailwindCSS
- TailwindCSS 的工具类主要作用于 Light DOM 的 class 组合；Web Components（Shadow DOM）里无法直接复用宿主的 class 工具体系。
- 设计系统更可持续的路线是“语义 token + CSS variables”，而不是把工具类耦合进组件内部实现。

## 约定（新增组件时）
- 组件内部：优先消费 `--zone-组件-语义`，并提供合理 fallback。
- 主题侧：优先覆盖组件级语义变量（如 `--zone-btn-*`），避免在 v1/v2 里复制粘贴大段组件样式。
